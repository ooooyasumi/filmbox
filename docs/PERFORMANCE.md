# 0.6.2 后台加载性能记录

2026-11-01，Apple M2 Pro，macOS 26.6.2，Swift 6.3，arm64。测试不读写正式资料库或原片，不连接真实网盘。

## 修复范围

- 全库预载只保存提供商封面并读取头部比例，实际浏览时才解码；后台预取不进入前台图片内存缓存。
- 前台缩略图缓存预算由 128 MiB／384 项降到 64 MiB／192 项；4096 大图不额外长期驻留共享缩略图缓存。磁盘预览、离线复用和原件保护保留。
- 磁盘命中与新生成共用三个解码名额，避免大量缓存图片同时解码。网格屏外单元及时释放图片宿主。
- 元数据合并改用项目索引与可见变更记录；文字只更新描述，比例只重算相关日期组／图片尺寸。通知每批最多 256 条，批次间让出主线程，元数据保存合并到约两秒一次。
- 下载状态按文件通知，任务计数增量维护，历史列表合并刷新。缓存字节建立后台账本，预算充足时不反复枚举全目录；凭据没有变化时不重复读写钥匙串。
- 搜索输入状态独立保存，连续输入停稳 170 毫秒后再筛选；清除立即生效，避免逐字符反复筛选一万条记录和旧绑定覆盖新输入。

## 同负载对比

使用对应版本的真实 Debug 对象及同一检查程序，顺序运行，没有同时编译或操作窗口。旧版本为 `93979bc`（0.6.1）；新版本为 0.6.2。共同负载包括一万条合成云记录、不可见元数据分批与通知突发、一万条传输状态流转、96 张具有独立缓存键的真实 JPEG 后台解码。额外功能测试另跑，不混入下表。

| 观测值 | 0.6.1 | 0.6.2 |
| --- | ---: | ---: |
| 一万条分批元数据处理 | 1.536 秒 | 0.521 秒 |
| 一万条传输状态处理 | 6.815 秒 | 0.856 秒 |
| 后台阶段最长主线程心跳延迟 | 254.0 毫秒 | 62.8 毫秒 |
| 不可见元数据触发可见／时间线结构更新 | 50／50 次 | 0／0 次 |
| 无关传输使指定文件观察失效 | 1 次 | 0 次 |
| 后台解码结束后仍存活的位图 | 85 张 | 0 张 |
| 后台位图阶段 RSS 增量 | 151.4 MiB | 50.1 MiB |
| 检查进程峰值 RSS | 258.3 MiB | 186.7 MiB |
| 一万条通知突发完成时间 | 0.512 秒 | 1.227 秒 |

突发通知总耗时增加，是因为分小批提交并在中间等待输入事件；目标是避免一次长时间占用界面。心跳每 20 毫秒运行一次，记录超出计划间隔的时间，不代表屏幕帧率。生成／读取合成目录的初始阶段单列，最长约 562–568 毫秒，没有算进后台阶段。

RSS 包含分配器、系统框架及临时缓冲，会随运行波动。本轮清理后的末尾 RSS 为旧版 117.8 MiB、新版 167.5 MiB，因此不宣称每个时刻占用都更低，也不把 64 MiB 图片预算当作整个应用的上限。位图生命周期断言、磁盘离线复用断言与峰值一起用于判断改动。

完整原始指标保存于 [对比数据](performance-results/2026-11-01-core-load.json)。复现方法见 [性能检查说明](../Tests/FilmboxPerformanceChecks/README.md)。

## 功能保护与测量边界

额外检查覆盖预载 256 张封面不生成显示位图、EXIF 旋转后比例正确且不冒充原图尺寸、突发合并期间同文件的新值最终胜出、前台缓存、大预览释放、磁盘离线命中与预算。网格、横卷及账号失效、缓存保护另做原生回归。

生产旧版六秒采样未捕获持续卡死，观察到主线程 SwiftUI 更新及整批比较的开销；短采样不能代表没有偶发无响应。这轮处理的是已测出的放大开销，没有修改或隐藏系统忙碌光标，也不保证外盘、系统内存压力、视频解码或第三方网盘永远不会等待。

独立真实窗口实验持续 45 秒，实际操作滚动、切换、选择、搜索及设置开关；完成96张后台 JPEG 解码，后台位图保留0张。最终主队列等待P95为32.4毫秒、最坏291.7毫秒，包含用户操作；旧版为163.7／1,073.3毫秒。两次操作时点不同，且新版多做清除、再次输入及设置开关，不作严格速度或内存比例推论。窗口报告见 [原始数据](performance-results/2026-11-01-window-load.json)。

独立真实窗口实验及最终生产升级结果记录在 [验收文档](ACCEPTANCE.md)。合成检查不等于真实百度／夸克的网络、限流与十万媒体吞吐量测试。
